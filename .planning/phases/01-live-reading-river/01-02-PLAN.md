## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Feed description HTML → sanitizer | Untrusted markup from the network. Primary XSS boundary. |
| Sanitizer → piece body node | Only this sink may receive HTML. |
| Attribute URLs → URL constructor | Root-relative paths must not resolve on this origin. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-10 | Tampering (XSS) | src/feed/sanitizeHtml.ts + src/ui/piece.ts | high | mitigate | DOMPurify 3.4.13 HTML profile at the insert sink. Title, date, permalink are text nodes (D-03, HTML-02). ASVS L1: high must mitigate; block on high. |
| T-01-11 | Tampering (XSS via URL) | uponSanitizeAttribute rewrite | high | mitigate | Rewrite href/src with new URL(..., PUBLISHER_ORIGIN) inside the hook so DOMPurify re-checks. Never rewrite after sanitize. javascript: stays rejected by the sanitizer URI check. |
| T-01-12 | Tampering (mXSS) | piece chrome | high | mitigate | createElement for chrome. Insert clean markup only into the dedicated body node. Do not concatenate sanitizer output into a wrapper string for a second parse (CVE-2026-65914). |
| T-01-13 | Spoofing | canonical permalink | medium | mitigate | Permalink is the feed item link as a text-node label on a real anchor (D-06). Not taken from description HTML. |
| T-01-14 | Information disclosure | empty state | low | accept | Shared quiet copy; do not leak stack traces to the visitor. |
| T-01-15 | Denial of service | large HTML body | low | accept | One log. Full sanitized body is the product. |
| T-01-SC | Tampering | npm install dompurify | high | mitigate | Pin 3.4.13 only. No @types/dompurify. No other production packages. |

ASVS L1. Block on high. T-01-10, T-01-11, T-01-12, and T-01-SC are high and must stay mitigated. Do not ship the HTML sink without the sanitizer.
</threat_model>
